# Content and publishing guide

Audience: content editors, publishers and business development staff.

## Roles

| Role                         | Can do                                                                                                    |
| ---------------------------- | --------------------------------------------------------------------------------------------------------- |
| Editor                       | Create and edit pages, services and projects; upload images; submit for review                            |
| Publisher                    | Everything an editor can, plus publish, unpublish, archive, approve case-study evidence, manage redirects |
| Business development         | View and work enquiries: status, owner, notes and follow-ups                                              |
| Business development manager | As above, plus CSV export and anonymising or deleting enquiries                                           |
| Marketing / analytics        | Dashboard reporting without personal data                                                                 |
| Administrator                | Users, roles, site settings, audit log, notification health                                               |

One person can hold several roles.

## How publishing works

1. **Save draft.** Saving never changes the public website.
2. **Preview.** Use _Preview this draft_ to see the page exactly as it will appear.
3. **Submit for review.** Editors submit; a publisher reviews claims, evidence, links and SEO fields.
4. **Publish** (publishers). The live site updates immediately. If a publisher returns the item, their note appears
   at the top of the publication panel.
5. **Changing live content** creates a new draft. The old version stays online until the new one is published.
6. **Unpublish** removes an item from the site; **Archive** retires it. Neither deletes it.

Publishing is blocked until required items are present (for example an SEO description). The publication panel
lists anything missing.

## Changing a URL

Change the URL slug and publish. The previous address redirects permanently to the new one. Do not reuse an old slug
for different content. Add redirects for pages from a previous website under **Redirects**.

## Writing service pages

Follow the page pattern: headline and value proposition, the business problem in plain language, capabilities,
outcomes, delivery approach, technology, related projects, FAQs and a call to action.

- Write about business outcomes before technology.
- Outcomes are shown as _illustrative_ unless marked _verified_. Only mark an outcome verified when evidence is on
  file and note where it is held. Never publish guaranteed savings or unsupported numbers.
- List only technologies the team can genuinely support.

## Case studies and client evidence

Never invent client names, logos, testimonials, technologies or results. The system enforces this:

- To name a client, set client permission to **Granted** only when written permission is on file. Otherwise leave
  the client name empty and use an anonymised description such as "Regional logistics provider".
- Results, testimonials, images and client names need a publisher's **evidence approval**. Record what was checked
  (for example "signed permission letter on file; metrics confirmed in client report dated …").
- Any change to that evidence clears the approval, so it must be checked again before the next publish.
- Use quotes exactly as approved and attribute them as agreed with the client.

## Images

Upload JPEG, PNG or WebP up to 5 MB. Images are resized, converted and stripped of hidden metadata such as location.
Always write alternative text that describes what the image shows; do not start with "Image of". Only upload images
you have the right to publish.

## Keeping content fresh

Each live item records when it was last reviewed. The dashboard lists content older than the review interval in Site
settings. After checking an item is still accurate, press **Mark content as reviewed**.

## Handling enquiries

- Open new enquiries from the dashboard or **Enquiries**. Assign an owner and move the status along:
  New → In review → Qualified → In progress → Won or Lost; or Not qualified / Closed.
- Use **Add note** for internal notes and **Record follow-up contact** when you have replied. The first follow-up sets
  the response time used in reporting.
- Notes are internal and never shown publicly or sent to the client.
- If someone else changed the enquiry while you were viewing it, you will be asked to reload before saving.
- Export only the columns you need, store files securely and delete them when finished. Every export is logged.
- For a deletion request, use **Remove personal data**: anonymise to keep anonymous statistics, or delete entirely.
